Describe todos los requisitos para poder ejecutar los proyectos en tu entorno local, así como poder envíar cambios a producción.

## Prerequisitos

Antes de iniciar, es recomendable:

- Solicitar acceso a 1Password para acceder a las diferentes integraciones que dispone el ecosistema.
- Solicitar las variables de entorno de cada repositorio a cada uno de los desarrolladores encargados.
- Solicitar usuario a AWS CLI para poder acceder a las bases de datos en modo port-forward.
- Instalar `AWS CLI` en su última versión disponible y la herramienta `kubectl`.
- Clonar los diferentes repositorios.
- Node v20.0.4 LTS o superior.
- Instalar dependencias según `package.json` con `pnpm i`.

<Danger>
  Nunca utilizar `npm` como administrador de paquetes para trabajar con los repositorios de SUBSCRIPCIONBOXCO-SAS.
</Danger>

## Cambios a producción

Github es el almacenamiento para todos los repositorios de la organización.

Para mantener una armonía en todos estos repositorios, se recomiendan los siguientes tips:

### Estructura de commits

- Utilizar la estructura convencional `action(module)`. Entre las acciones: `feat`, `refactor`, `fix` y demás. Siempre agregar descripción adicional para detallar los cambios realizados.
- Crear tu rama en local, y luego enviar `pull request` hacía `origin/develop-rf` para aprovación del encargado de CI/CD.

<Info>
  En lo posible, no envíar cambios directo a las ramas `origin/develop-rf`, `origin/master` o `origin/main`
</Info>

### Pruebas

Si bien, en **Hi Beauty** no contamos con un ambiente de pruebas ni scripts para realizarlas, siempre es recomendable realizar pruebas exhaustivas sobre los cambios realizados antes de envíar cambios a producción.
